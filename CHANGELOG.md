# Changelog

All notable changes to pg_procrustes are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- `layout.clauses.align: right` — the "river" style: the keywords of a statement's clauses are right-aligned on a common edge (the longest one, e.g. `GROUP BY`) and their content hangs after them (`SELECT a.id,` / `       a.name` / `  FROM accounts` / ` WHERE …`), `JOIN` lines hang under the content of `FROM` instead of widening the river, the columns of `INSERT INTO t (a, b)` line up below the first one, and each query of a `UNION` has its own width. Meant for `content.first_item: inline`; only clauses that are broken take part. Stays idempotent for statements that start indented (`BEGIN; … COMMIT;`, PL/pgSQL bodies: the padding of the first keyword is told apart from the indentation by what all lines of the statement share). Documented in README, reference config and Config Builder (all languages); tests in `internal/layout/river_test.go`
- `keyword_paren_spacing: preserve | add | remove` (default `preserve`) — the space between a keyword or operator word and its `(`, apart from function calls (`call_paren_spacing`): `add` gives `IF (a) THEN`, `WHERE (a = 1) AND (b IN (1, 2))`, `VALUES (1, 2)`, `EXISTS (SELECT 1)`, `ON CONFLICT (id)` (and puts a space between a `)` and the keyword after it), `remove` gives `IF(a)`, `IN(1, 2)`; all shipped templates (`postgresql`, `modern`, `ai`) set `add`; `count(*)`, `coalesce(a, b)`, `varchar(10)`, `INSERT INTO t(a, b)`, `x AS y(a, b)` and keyword-spelled functions (`left(…)`, `replace(…)`, `format(…)`, `json_object(…)`, also inside PL/pgSQL expressions) stay with their own rules. Documented in README, reference config, website, `llms-full.txt` and the Config Builder (all languages); tests `TestKeywordParenSpacing` and test-matrix variants

### Fixed

- Operators that are names stay tight to the punctuation beside them: `ORDER BY a USING <, b USING >` and `OPERATOR(pg_catalog.<)` (with `operator_spacing: normalize` they came out as `USING < ,` and `pg_catalog. <`, which the next run changed again)
- Layout idempotence found with `scripts/stmt_matrix.go` (every statement of a corpus through several configs, bare and inside `DO $$ … $$`): a statement that opens with a parenthesis and continues with a set operation (`(SELECT …) INTERSECT SELECT …`) no longer starts with the blank lines of `layout.union.blank_line` and gains two more on every run; `content.wrap_expressions: wrap` decides whether an item is too long by its length without the blanks of a hand-aligned list (the wrapped item loses them, so the next run found it short enough and joined it again). Tests in `internal/layout/review_fixes_test.go`
- Function calls in a `VALUES` list (`INSERT … VALUES (now(), coalesce(a, 0))`) and in `LIMIT` / `OFFSET` follow `functions.case` like those in the select list (they kept the case they were written in). Golden case `plpgsql_full` (the `now()` calls)
- PL/pgSQL bodies: the SQL statements of a body — `CREATE TABLE`, `INSERT`, `CREATE VIEW`, `ALTER`, `GRANT`, `EXPLAIN`, `COPY`, … — are parsed one by one and read the same as at the top level of a file: columns named like keywords (`data`, `name`, `label`, `oid`) and column lists (`INSERT INTO t (char)`, was rewritten to `character`) are no longer written as keywords or types, `FOR VALUES IN` / `FOR ROLE x IN SCHEMA` are no loops, and a `WITH (…)` of `CREATE VIEW … WITH (security_barrier)` is no CTE list. Checked with `scripts/body_diff.go` (formats every statement of a corpus at the top level and wrapped in `DO $$ … $$`, and compares); golden case `plpgsql_body_statements`
- PL/pgSQL bodies: `GRANT SELECT, UPDATE, INSERT ON …` / `REVOKE …` are no longer broken up by the clause layout (the privileges were taken for statements: `GRANT SELECT ,` / `UPDATE , INSERT ON …`); `FOR EACH ROW` of `CREATE TRIGGER` (and `IN ROW EXCLUSIVE MODE`) in a body are no longer read as loop variables and written as `FOR each row execute function`. Golden case `plpgsql_utility_statements`
- `DO LANGUAGE plpgsql $$ … $$` (the language before the body) is formatted like `DO $$ … $$ LANGUAGE plpgsql`: its PL/pgSQL body was left exactly as written; a body in another language (`DO LANGUAGE plpython3u`) still is. Golden case `do_language_first`
- Names that are also keywords are no longer upper-cased where the parser's tree was not followed: aliases and columns inside `EXPLAIN`, `PREPARE`, `DECLARE … CURSOR`, `COPY (query)` and `MERGE` (its source, conditions and actions) — `EXPLAIN … SELECT 1 AS type … ORDER BY type`, `MERGE … USING (…) AS source`; an alias in a `MERGE` / `DELETE … USING (…)` source gets `aliases.as`; `expr AS type` inside a `PERFORM` of a PL/pgSQL body; `persons.exit` (a PL/pgSQL keyword after a dot is a column). Golden case `keyword_alias_names`
- The names after `AS` in the arguments of `XMLFOREST` / `XMLATTRIBUTES` (`xmlforest(x AS costs, y AS number)`) are element and attribute names, not keywords: they follow `columns.case` instead of being written as `COSTS` / `NUMBER` (also in PL/pgSQL bodies). Golden case `xml_alias_names`
- Layout: the content that follows a line comment on its clause keyword line (`WHERE --c` / `a IS NOT NULL`) stands below the keyword like the content of a broken clause (it was left at the margin when the clause stayed on one line, and at the old indent with `layout.clauses.align: right`, which the next run moved). Test `TestCommentAfterKeywordHangsContent`
- Idempotence found on the PostgreSQL source tree and a real accounting schema: `quoted_identifiers: remove_safe` keeps the quotes of `"date"` / `"text"` (type and literal names) where the parser does not place the name (PL/pgSQL expressions) — unquoted, the next run wrote it as the type `DATE`; an inserted `AS` no longer keeps the alignment padding before it (`sum(b)      AS x`, collapsed on the next run); the arguments of a call that stand left of the item (`SELECT hmac(` / `'a',` at the margin) end one level below the call at once instead of on the second run; a `USING (…)` / `) AS f` after a multi-line derived table in a `JOIN` no longer moves the item once more on every run; a closing parenthesis indented with blanks above a body indented only with tabs is left to the generic indentation. Golden case `idempotence_real_world`
- PL/pgSQL bodies: parameters and variables spelled like keywords (`sql`, `name`, `type`, `key`, `data`, …) are no longer written as keywords in the body's expressions (`RETURN SQL || NAME`, `KEY = KEY + 1`, `SELECT … INTO TYPE`): the names of the function's parameters, of `DECLARE` sections and of `FOR` / `FOREACH` loops are known to the body (`xmlelement(name x)` keeps its keyword). Golden case `plpgsql_keyword_like_variables`
- Layout: `FOR ORDER BY` of `CREATE OPERATOR CLASS` / `ALTER OPERATOR FAMILY … OPERATOR n op FOR ORDER BY float_ops` is no longer taken for the `ORDER BY` clause of a query (it broke the line there and joined the next `OPERATOR` / `FUNCTION` items onto it). Test in `internal/layout/review_fixes_test.go`
- `EXTRACT(… FROM …)` and `x AT TIME ZONE y` no longer lose their capitals: the parser reports them as `pg_catalog.extract` / `pg_catalog.timezone` calls located at the keyword, which was classified as a schema name and written in the `schemas` case (`extract(MONTH FROM _at at TIME ZONE …)`); a keyword the text does not spell as `schema.name` is now left to the keyword rules
- Layout: a multi-line item that opens a parenthesis — a CTE body (`v AS` + `(` … `)`) or a `VALUES` row written over several lines — is shifted as a whole into the item's indent (its body ends up deeper than the parentheses, also when the input had it further left than the `)`, and a body that is deeper already is not moved again on the next run; only for a parenthesis that opens on the first line or alone on the second); before, the `(` and the body stood at the indent of the clause and the closing `)` at the margin (`WITH` / `    v AS` / `(` / `    …` / `)`; `VALUES` / `    (` / `    'a',` / `),`) when the source had the `)` further left than the clause content. Test in `internal/layout/paren_item_test.go`
- PL/pgSQL control flow: a one-line `IF a THEN x; ELSE y; END IF;` gets no inserted whitespace any more with `control_flow.if.body_indent: indent` (every run added blanks before `RETURN` and `ELSE`, so the output was not idempotent): only lines of their own are indented and only keywords that start a line get an indent
- Layout inside PL/pgSQL bodies: a statement that follows another one on the same line (`PERFORM f(1); PERFORM f(2);`, `SELECT … INTO a; SELECT … INTO b;`) is no longer broken up by `layout.clauses.break` — it has no line of its own to take an indent from, so its lines landed at the margin and moved on every run (not idempotent); it keeps its place (use `statement_break: always` to give each statement its own line). Golden case `statement_break_plpgsql`
- Layout: a comment line between two list items (`),` / `-- note` / `b AS (…)` in a `WITH` list, a `VALUES` or column list) is laid out the same on every run: with `comma_position: end` the comma stays on the line of the code above the comment (it was put in front of the comment, `)` / `, -- note`, which the next run read as a trailing comment) and the first line of the item below it takes the item's indent like the lines under it (it was left at the margin). Found by checking the 4 700 migrations of a real project for idempotence; test in `internal/layout/paren_item_test.go`
- A function named like a PL/pgSQL keyword (`CREATE FUNCTION pg_temp.assert(…)`, `DROP FUNCTION s.raise(…)`) keeps its name's case with `plpgsql_keywords.case: upper` (it was written `pg_temp.ASSERT` while its calls stayed `assert`); the RAISE levels `debug`, `info`, `notice`, `warning` are keywords only after `RAISE` (a record variable `info` and `info.client_id` were upper-cased); `inline_spacing: normalize` turns a single tab between tokens into a space too (a join line with tab-separated parts stayed untouched). Golden case `plpgsql_keyword_like_names`
- `statement_break: always` inside a PL/pgSQL body keeps the indentation of the line it breaks (`IF a THEN RETURN 1; ELSE RETURN 2; END IF;` came out with `ELSE` and `END IF;` at the margin)
- Names in the column list of a table alias, CTE, view or `CREATE TABLE … AS` (`FROM f() AS x(database text, class text)`, `AS u(a, b)`, `WITH c(a, b) AS …`, `CREATE VIEW v (a, b) AS …`) are columns, not keywords: `database`, `class`, `object` were upper-cased
- Layout: `SELECT … FOR UPDATE | NO KEY UPDATE | SHARE | KEY SHARE` is a clause of its own (it was glued to the `WHERE` line); a `--` comment line in front of `CREATE FUNCTION` / `CREATE TABLE` / … no longer switches the `layout.ddl.*` rules off for that statement or counts for its length; `RETURNS TABLE (…)` follows `ddl.create_function.params` (one column per line when always, or when its line is longer than `line_length`) instead of being joined into one line of any length; the arguments of a multi-line call whose line ends with `(` under a broken `PERFORM` / item (`f(` / `_a => 1,` / `_b => 2);`, without a subquery among them) stand one level below the call. Tests in `internal/layout/review_fixes_test.go`
- `SELECT DISTINCT ON (u.id) u.id, … FROM unnest(…) AS u(id, d)` no longer gets a bogus `AS` (`DISTINCT ON (u.id) AS u.id`, invalid SQL) with `aliases.as: add`: a name after a `)` that matches the alias of a table function is not taken for that alias when it is followed by `.` or the parenthesis closes a `DISTINCT ON` key list. Golden case `extract_at_distinct_on`

## [0.5.0] — 2026-11-07

### Added

- `pg_procrustes --lsp`: a Language Server (LSP over stdio, standard library only, new package `internal/lsp`) for VS Code, Zed, Neovim, Helix, Emacs, Sublime Text and any other editor with an LSP client — `textDocument/formatting`, `textDocument/rangeFormatting` (backed by `formatter.FormatRange`) and syntax errors as diagnostics (error; warning with `syntax_errors: skip`; published after the last queued change). Edits cover only the lines that differ, positions are UTF-16 as the protocol requires, the config is looked up per document and re-read on every request (`-c` or `initializationOptions.configPath` fix one), and a document that does not parse or a result that would be empty is never turned into an edit. README gets setup examples
- Editor extensions in `editors/`: **VS Code** (`editors/vscode`, TypeScript client of `pg_procrustes --lsp` with settings `pgProcrustes.path` / `configPath` / `trace.server`, finds the binary in the usual install folders, restart and show-output commands, packaged with `npm run package`) and **Zed** (`editors/zed`, Rust/WASM extension that registers `pg_procrustes` as a language server for SQL and honours `lsp.pg_procrustes.binary` and `initialization_options`). The website (all six languages), `llms.txt`, `AGENTS.md` and `CONTRIBUTING.md` describe them. CI builds both (`editors` job: `npm run package`, `cargo check --locked`). Not published to a marketplace yet; the READMEs there explain building and installing from source
- `--lines START:END` (or `--lines N`) formats only the statements that touch those lines of a single file or of stdin and copies the rest exactly as written — for range formatting in editors. A statement that is only partly inside the range is formatted completely, statements outside it are not parsed (an error elsewhere does not matter), `syntax_errors` applies to the selected ones, `-- pg_procrustes: off` regions and line numbers of CRLF files are respected, and the whole-text settings (`blank_lines`, `blank_lines_between_statements`, `statement_break`, `semicolons: add`, `trailing_newline`, `line_endings`) are not applied. Library: `formatter.FormatRange`. The Neovim plugin gets `:'<,'>PgProcrustesFormat` and conform.nvim range formatting (`range_args`)
- DDL layout for the remaining statements, all `preserve | never | always | auto` (default `preserve`) and left alone when the statement has a `--` comment: `layout.ddl.create_view.columns` (column list of `CREATE [MATERIALIZED] VIEW v (a, b)`, one name per line, `)` on its own line), `layout.ddl.create_trigger.break` (`CREATE [CONSTRAINT | EVENT] TRIGGER`: timing and events, `ON`, `FROM`, `REFERENCING`, `FOR EACH`, `WHEN`, `[NOT] DEFERRABLE`, `EXECUTE` each on an indented line), `layout.ddl.create_policy.break` (`ON`, `AS`, `FOR`, `TO`, `USING`, `WITH CHECK`), `layout.ddl.grant.break` (`GRANT` / `REVOKE`: `ON`, `TO` / `FROM`, `WITH …`, `GRANTED BY`, `CASCADE`; the privilege and object lists stay as written), `layout.ddl.create_type.break` (the parenthesised list of `CREATE TYPE` — enum labels, composite attributes — one entry per line) and `layout.ddl.create_sequence.break` (options of `CREATE` / `ALTER SEQUENCE`: `AS`, `INCREMENT`, `MINVALUE`, `MAXVALUE`, `START`, `RESTART`, `CACHE`, `CYCLE`, `OWNED BY`). Documented in README, the reference config and the Config Builder (all languages); new golden cases `ddl_more` and `ddl_more_auto` and test-matrix variants
- DDL layout for the rest of the common statements (`preserve` by default, left alone when the statement has a `--` comment): `layout.ddl.alter_table.constraints: preserve | always | auto` puts the parts of `ADD [CONSTRAINT name] PRIMARY KEY | FOREIGN KEY | UNIQUE | CHECK` (the constraint type, `REFERENCES`, `MATCH`, `ON DELETE` / `ON UPDATE`, `[NOT] DEFERRABLE`, `NOT VALID`) on indented lines below the action; `layout.ddl.create_partition.break` (`CREATE TABLE … PARTITION OF`: `PARTITION OF`, `FOR VALUES` / `DEFAULT`, `PARTITION BY`, `WITH`, `TABLESPACE`), `layout.ddl.drop.break` (`DROP TABLE | VIEW | INDEX | SEQUENCE | SCHEMA | TYPE | …` with several names: one per line, `CASCADE` / `RESTRICT` on a line of its own), `layout.ddl.create_domain.break` (`DEFAULT`, `COLLATE`, `NOT NULL`, `CONSTRAINT` / `CHECK`) and `layout.ddl.create_extension.break` (`WITH SCHEMA`, `VERSION`, `FROM`, `CASCADE`) take `preserve | never | always | auto`. README, reference config, Config Builder (all languages), golden cases `ddl_rest` / `ddl_rest_auto` and test-matrix variants included
- A directory as argument is searched recursively for `*.sql` files (`pg_procrustes -w sql/`, `--check .`; hidden directories and `node_modules` are skipped), and `**` in a pattern matches any number of directories (`'migrations/**/*.sql'`) — before, a directory was an error and `**` behaved like `*` (README and usage promised `migrations/**/*.sql`, which only worked where the shell expands `**`). Files named on the command line are formatted whatever their extension; `--out-dir` keeps the path below the searched directory instead of flattening everything into one folder
- `--stdin-filepath <path>`: the path the text on stdin belongs to (it need not exist); the config is looked up from its directory. The Neovim plugin and conform.nvim pass it (`$FILENAME`), as do the Zed, apheleia and ALE examples in the README

### Changed

- README badges: the Go Report Card badge is gone (the service was sunset and its badge reads "retired"); CI now reads the `main` branch only (a failed run on a PR branch no longer turns it red) and the badges grow into three rows: build / release / Go Reference / Go version / license / stars; Homebrew, platforms, downloads, website and Config Builder; parser (`libpg_query`), editors (LSP, Neovim, VS Code) and pre-commit
- Documentation brought up to date: the website (`docs/index.html`) gains a "Language server (LSP)" section, a "DDL statements" section (`layout.ddl.*`) and the `--lines`, `--stdin-filepath`, `--lsp` flags, directory / `**` usage; `docs/llms.txt` and `docs/llms-full.txt` (which was missing the LSP, `--lines` and later changes) are regenerated; the project tree in `CONTRIBUTING.md` matches the real layout; sitemap dates refreshed. The new website texts are translated into all six site languages (cs, es, de, fr, pt, it)
- The release workflow (`release.yml`) runs `ci.yml` first (now also a reusable `workflow_call`) and creates the release only when it is green; `make install-hooks` activates `.githooks/pre-push` (gofmt, `make lint`, tests — the same checks as CI, skip with `--no-verify`)
- `make prepare-release` / `make release` run `make lint` before the tests (CI already linted pushes and PRs, the local release path did not); `golangci-lint` is pinned to v2.15.0 in one place (`GOLANGCI_LINT_VERSION` in the Makefile, which `make lint` installs on a mismatch and CI reads), instead of `@latest` locally and v2.2.1 in CI; the 22 outstanding `golangci-lint` findings (unchecked `Close` / `Write` / `Remove` errors, two ineffectual assignments, an unused helper) are fixed
- The config file is now looked up from **the directory of each file** (then its parents, then — if nothing is found — the working directory and its parents) instead of only from the working directory, so the result no longer depends on where the program is run and files of several projects can be formatted in one call; `-c` still wins, text on stdin uses `--stdin-filepath` (else the working directory), `--print-config [file]` shows the config of that file. Library: `config.FindConfig(dir)`, `config.ConfigPathFor(file)`
- `ON CONFLICT (target) DO UPDATE` / `DO NOTHING` stays on one line when clauses are broken (it was split into `on conflict` / `(a) do update`); `SET`, `WHERE` and `RETURNING` follow on lines of their own

### Fixed

- **Function bodies in other languages were formatted as SQL**: the `$$ … $$` body of a `LANGUAGE plpythonu` / `plperl` / `pltcl` / `c` function (or `DO LANGUAGE …`) came out with Python text upper-cased (`plan` → `PLAN`), quotes removed from `["int4"]` and a `;` added. Only `LANGUAGE sql` and `plpgsql` bodies (and `DO` blocks without a language) are formatted now
- **Second runs no longer change the text** (found by formatting ~111,000 real `.sql` files with `postgresql`, `ai` and `modern`: 450 problem reports, now none on the files that had them). Several of these added another level of indentation on every run: a statement that starts indented (`    select …` inside `BEGIN; … COMMIT;`) is laid out as if it started in column 0 and moved back, so the layout no longer reads differently on the next run; a row or column with comment lines in front of it was judged by the comment's indent, a comment line that ends a list item was moved on every run, and comment lines inside an `INSERT` column list with leading commas went behind the comma (`, --`); `CREATE INDEX … WHERE` with the condition on a line of its own hangs from the line the keyword really stands on; a line break beside a binary operator is removed with `arithmetic_spacing: compact` (`CAST(… +\n interval …)` lost it only on the second run). Tests: `TestStabilityOfCorpusShapes` formats nine such shapes three times with each shipped template
- Found by running `scripts/corpus_check.go` on the PostgreSQL regression tests: `operator_spacing: compact` no longer glues two operators into another one (`COMMUTATOR = ===` became the operator `====`, `= ~b` became `=~b`; the blank stays when the joined text would be scanned differently); a VALUES row whose leading comma follows comment lines (`-- note` / `, (2)`) no longer gets the comma twice (`, , (2)`); `aliases.as: remove` keeps the `AS` of `JOIN … USING (i) AS x` (the join alias of PostgreSQL 14+ — it is required) when another statement of the file has a table function aliased `x`
- **String constants were being changed** (found by comparing their text before and after on ~111,000 real `.sql` files; `pg_query` fingerprints ignore constant values, so nothing caught it): layout re-indented the lines of a multi-line `'…'` constant (`'a⏎b'` became `'a⏎  b'` with the `modern` template; every layout option that joins or indents lines was affected), `blank_lines` squeezed the blank lines inside one, and the pattern of `a SIMILAR TO 'AB'` was lower-cased (the parser reports that syntax as a call located at the keyword, and the position computed from it landed on the string). Layout now works around multi-line constants, `blank_lines` skips them (also inside function bodies), and the test matrix and `scripts/corpus_check.go` (new problem kind `string-changed`) compare the constants' text
- Found by running `scripts/corpus_check.go` on ~111,000 real `.sql` files: a commented-out last row or column after the final comma (`--, (5, 6)` before the `;`) no longer gets a separating comma, which left a dangling `,` and made the output unparseable (affected `postgresql`, `ai` and `modern`); with `layout.ddl.create_table.align` and leading commas a comment line between two columns is no longer pulled up behind the previous column on the second run
- `CREATE TABLE … PARTITION OF p FOR VALUES IN (…)` / `FROM (…) TO (…)` was cut into clauses (`for values` / `in (1, 2, 3)`, a `FROM` clause) when clauses were broken; the statement is now left whole
- `FROM` of `CREATE CONSTRAINT TRIGGER … FROM table` is no longer taken for the `FROM` clause of a query

## [0.4.0] — 2026-11-06

### Added

- **Templates:** a config file can start from other config files with `template: name` (an installed template), `template: path/to/file.yaml` (relative to the file that names it) or a list of them, applied in order; the file's own settings win. Maps merge key by key, lists and scalars are replaced, templates may use `template:` themselves (cycles are errors). Templates are ordinary config files in the new `templates/` folder (`postgresql` ≈ what PostgreSQL itself prints, `ai` = lean for LLM prompts, `modern` = lower-case keywords for syntax highlighting, one item per line with leading commas, no alignment padding: friendly to git, wide screens and AI); they are not embedded in the binary but installed next to it — release archives and the Homebrew formula carry `templates/`, `make install PREFIX=…` copies it to `PREFIX/share/pg_procrustes/templates`, and lookup also covers `$PG_PROCRUSTES_TEMPLATES` and the user's config directory. New flags `--install-templates` (downloads the `templates.zip` of the matching GitHub release into the user templates directory — for `go install` users; `--templates-from <url|zip|folder>` picks another source; the release workflow uploads `templates.zip`), `--print-config` (effective configuration with every option, plus the files it was built from) and `--list-templates`. Library users get `Config.Sources`, `config.TemplateDirs`, `config.ListTemplates` and `Config.YAML`
- `layout.subquery.break: preserve | never | always | auto` (default `preserve`): lays out parenthesised subqueries and CTE bodies — `(select …)`, `(with …)`, `(values …)` — with the same rules one level deeper: `(` stays on its line, the body goes below it, `)` gets a line of its own (`never` joins them onto one line, `auto` opens only those on a line longer than `line_length`; a subquery with a `--` comment is left alone). With `always`, a `content.break: auto` list that holds a subquery is broken one item per line. Nested subqueries, function bodies (including `exists (select …)` in an `if` / `elsif` / `while` condition) and leading commas are handled; the `modern` template uses it
- `WINDOW name AS (…)` is a clause of its own: `layout.clauses.window` and `layout.content.window_list` (inherit the general settings) put it on its own line and one definition per line, like `group by`
- `plpgsql_assignment: preserve | colon_equals | equals` (default `preserve`): writes the assignment operator of PL/pgSQL statements and DECLARE defaults as `:=` or `=`; named arguments (`f(a := 1)`), comparisons, `UPDATE … SET`, `USING` options and cursor queries are left alone. The `postgresql` and `modern` templates use `colon_equals`
- `layout.paren_indent.open: preserve | own_line` (default `preserve`): `own_line` moves the `(` of a block that spans lines from the end of its line onto a line of its own, in the column of the matching `)` (`from (` / `select 1` / `) s` becomes `from` / `(` / `select 1` / `) s`); parentheses already first on their line, after a comma or `AND`/`OR`, or followed by a comment are left alone
- **Config Builder:** a magnifier button next to Template / Load / Preview opens a search row below the buttons (pressing it again hides the row and clears the search) that narrows the list as you type (every word must occur in an option's key, label, description or value names; accents and case are ignored, in the page's language; matches are highlighted, groups without a match are hidden and dimmed in the navigation, `/` jumps to the box, Esc clears it) with a “changed only” switch; the description panel at the bottom can be resized by dragging the grip on its top edge (or ↑/↓ on it; double-click collapses / restores it) and the height is remembered; on a narrow screen the option's key stands on the label's line, against the right edge, instead of on a line of its own
- `-- pg_procrustes: off` / `-- pg_procrustes: on` (also `/* … */`): the lines between them, directives included, are copied to the output untouched — in a file and between the statements of a function body. Without a closing `on` the region runs to the end of the input; error positions of `syntax_errors` still refer to the original lines
- `wrap_expressions: wrap` also lays out a long window specification: `sum(x) OVER (PARTITION BY … ORDER BY … ROWS BETWEEN …)` puts `PARTITION BY`, `ORDER BY` and the frame on a line each (a window with a single clause stays on one line)
- `layout.subquery.break` now also opens subqueries that contain `--` comments (the comment keeps its line; a `)` is never put behind a comment)
- `statement_break: preserve | always` (default `preserve`): `always` starts every statement that shares a line with the previous one (`select 1; select 2;`) on a line of its own; a comment on the line of a `;` stays with its statement and blank lines are untouched (`blank_lines_between_statements` also separates statements and takes precedence)
- `none` for the alignment options `comments.align_trailing`, `layout.content.align_aliases` and `layout.content.align_set`: removes the padding and leaves exactly one space before the trailing `--` comment / `AS` / `=` (`layout.ddl.create_table.align` already had `none`)

## [0.2.0] — 2026-06-30

### Added

- `exceptions` list on all casing sections (`reserved_keywords`, `keywords`, `data_types`, `literals`, `operators`, `schemas`, `tables`, `functions`, `conditional_functions`, `system_functions`, `aliases`, `columns`, `plpgsql_variables`, `plpgsql_keywords`) — individual identifiers can be pinned to a specific case regardless of the section setting
- `operator_spacing: compact` — removes all spaces around symbolic operators (`=`, `!=`, `<>`, `<`, `>`, `<=`, `>=`, `||`); complements the existing `normalize` option
- `comma_spacing: compact` — removes all spaces around commas; complements `normalize`
- `layout.content.first_item` — new orthogonal setting controlling where the first item lands when content breaks (`break` = new indented line, `inline` = keyword line); replaces the former `first_inline` break mode
- `--backup` CLI flag — saves the original file with a given extension before overwriting in-place (`-w`)
- `--out-dir` CLI flag — writes formatted files into a target directory instead of stdout

### Changed

- `layout.content.break: first_inline` removed; replaced by `layout.content.first_item: inline` combined with any non-preserve break mode — existing configs using `first_inline` must be migrated

### Fixed

- Dollar-quoted blank line handling: blank line rules now apply only inside function bodies (after `AS` or `DO`), not to every `$$`-delimited string
- `order_asc: add` scanned past a semicolon into the next statement's SELECT list and inserted spurious ASC keywords there
- `cast_style: operator` emitted a double space when a CAST expression immediately followed a symbolic operator such as `||`
- `layout.union.blank_line` split `UNION ALL` onto two lines because the keyword length was tracked as 1 (only `UNION`), leaving `ALL` as clause content
- `layout.union.blank_line` did not emit the configured blank line when no tokens appeared between a `UNION ALL` and the following `SELECT`

## [0.1.1] — 2026-06-22

### Fixed

- `peekNext` in PL/pgSQL scanner used `break` instead of `continue` when encountering `(` or `[`, causing it to stop rather than skip past the token and find the next real one
- Loop in alias detection (after `AS`) rewritten as a plain `if` — it only ever checked the immediately following token, never iterated
- Removed unused `prefixGap` field from the `statement` struct in the layout layer

## [0.1.0] — 2026-06-22

Initial release.

### Added

**Keyword & identifier casing**
- `reserved_keywords.case` — SELECT, FROM, WHERE, JOIN, …
- `keywords.case` — ANALYZE, CASCADE, VERBOSE, …
- `data_types.case` and `data_types.form` — long / short / long_no_space forms
- `literals.case` — TRUE, FALSE, NULL
- `operators.case` — AND, OR, NOT, IN, IS, LIKE, BETWEEN, …
- `schemas`, `tables`, `columns`, `functions`, `conditional_functions`, `system_functions`, `aliases` casing
- `aliases.as` — add / preserve / remove the AS keyword

**Punctuation & spacing**
- `trailing_whitespace` — strip trailing spaces
- `semicolons` — add / remove statement semicolons
- `inequality_op` — normalize to `!=` or `<>`
- `join_form` — short (JOIN) or long (INNER JOIN, LEFT OUTER JOIN, …)
- `operator_spacing` — normalize spacing around `=`, `!=`, `<>`, `<`, `>`, `<=`, `>=`, `||`
- `blank_lines` — cap consecutive blank lines (max_1 / max_2 / max_3)
- `paren_spacing` — add or remove spaces inside parentheses
- `quoted_identifiers` — remove unnecessary double-quotes (`remove_safe`)
- `schema_qualification` — strip `public.` prefix
- `cast_style` — normalize between `::` and `CAST(… AS …)`
- `order_asc` — make ASC explicit or implicit
- `not_in` — normalize between `NOT IN` and `<> ALL`

**Layout**
- `layout.clauses.break` — put each SQL clause on its own line (preserve / never / always / auto)
- `layout.clauses.align` — clause keyword alignment (same / indent)
- Per-clause overrides: `from`, `join`, `where`, `group_by`, `having`, `order_by`, `limit`, `offset`, `values`, `on_conflict`, `set`, `using`, `returning`, `with`, `exception`
- `layout.content.break` — break SELECT list at commas, WHERE/HAVING/JOIN at AND/OR
- `layout.content.align` — content alignment (same / indent)
- Per-section overrides: `select_list`, `where_conds`, `join_on`, `group_list`, `order_list`, `set_list`, `values_list`
- `layout.union.blank_line` — blank lines around UNION / INTERSECT / EXCEPT
- `layout.indent` — spaces / tab, size, normalization
- `layout.case.break` — expand or collapse SQL `CASE … END` expressions (never / always / auto)
- `layout.case.indent` — WHEN/ELSE indentation relative to CASE

**PL/pgSQL**
- Dollar-quoted bodies (`$$`, `$func$`, …) detected and formatted recursively
- `layout.dollar_quote.plpgsql.keyword_indent` — DECLARE / BEGIN / END indentation
- `layout.dollar_quote.plpgsql.declare` — DECLARE section indent and blank lines
- `layout.dollar_quote.plpgsql.begin_body` — BEGIN body indent and blank lines
- `layout.dollar_quote.plpgsql.declare_when_empty` — keep or remove empty DECLARE
- `layout.dollar_quote.plpgsql.end_semicolon` — semicolon after final END
- `control_flow.if` — IF / ELSIF / ELSE / END IF body indent and blank lines
- `control_flow.loop` — LOOP / FOR … LOOP / WHILE … LOOP / END LOOP body indent and blank lines
- `control_flow.case.simple` — CASE expr WHEN … formatting (when_indent, then_break, then_indent, body_break, body_indent)
- `control_flow.case.searched` — CASE WHEN … formatting (same settings)
- EXCEPTION section body formatted with the same control_flow rules

**CLI**
- Format files in-place (`-w`), print to stdout, or read from stdin
- `--check` mode for CI / pre-commit hooks (exit 1 if any file would change)
- `--diff` mode — print unified diff without writing
- `-v` / `--version` — print version
- `-c` — explicit config file path; auto-detection walks up from the current directory
- Glob expansion (`migrations/**/*.sql`)
