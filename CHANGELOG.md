# Changelog

All notable changes to pg_procrustes are documented here.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Changed

- `FuzzTemplates` (`go test ./formatter -run '^$' -fuzz FuzzTemplates`): fuzzes the shipped templates (postgresql, ai, modern) for parseable and idempotent output, next to `FuzzFormat`'s single options
- `--check --diff` prints the diff of every file that would be reformatted (and exits 1); `--diff` was ignored when `--check` was given
- A config file with an option that does not exist is an error (`parse config x.yaml: line 2: unknown option "casee"`) instead of a setting that silently does nothing; with `template:` the error names the file the option stands in. A config that still carries an option removed in an earlier version has to drop it. Test `TestLoadRejectsUnknownOptions`

### Fixed

- A comment between `ON` and `CONFLICT` (`on -- note` / `conflict (a) do update …`) hid the `ON CONFLICT` clause: the layout took it for more rows of the `VALUES` list and put commas in (`(0),` / `ON --` / `CONFLICT(a),`, which does not parse), and the conflict target columns got no `columns.case`. Found by `FuzzFormat` (seed `06b8ccaed999827c`)
- A clause keyword of several words broken over lines in the source (`insert` / ` into`, `order` / `by`) was written with that line break, so the content hung from the line of its second word and the next run placed it differently (not idempotent); such keywords are written on one line (`INSERT INTO`, `ORDER BY`). Found by `FuzzFormat` (seed `a98364f7bb3e300a`); test `TestKeywordOfSeveralWordsIsJoined`
- With a layout configured, a vertical tab or form feed at the start of a line between tokens (`a` / `\v(` / `)`) was no indent to the layout but stood in front of the line's code, so every run indented the line further (not idempotent); between tokens they become blanks when the layout re-indents the lines. Found by `FuzzFormat` (seed `993a31537814709f`)
- `layout.content.break: always` with `AND` / `OR` followed by a form feed or vertical tab (`or \f0`): the condition kept the character at the start of its line, which the next run trimmed (not idempotent); all SQL white space after the operator is taken off. Found by `FuzzFormat` (seed `29c4519970b3236e`)
- `INSERT INTO t -- note` with the column list on the next line: the layout joined `(a, b)` to the line of the comment, where it became part of it (`INSERT INTO t -- note (a, b)`, a different statement). The column list stays below the comment. Found by `FuzzFormat` (seed `1d2651ec61921c11`)
- `layout.ddl.create_table.align: none | types | all`: a block comment of several lines above a column (`/*` / `*/` / `a int`) kept the indent of its lines while the column name lost its own, so the re-indentation moved the comment's lines one level further on every run (not idempotent). Found by `FuzzTemplates` (seed `5a8759ee872940b3`); test `TestCreateTableBlockCommentAboveColumnIsStable`
- `logical_operator_position: end` (or `preserve` reading it): an `AND` / `OR` with a comment glued to it (`or--c`) was not recognized as the operator of its condition, so it stayed at the start of the line; the next run, which found `or --c`, moved it (not idempotent). Found by `FuzzTemplates` (seed `bfa92418e90fcd3e`)
- An alias spelled like a keyword was taken for a bare label wherever `SELECT 1 word` parses, but the parser reads some of them as the next part of the expression in other places: `!0 at` (AT TIME ZONE), `count(*) over` (a window). `aliases.as: remove` dropped their `AS` and `quoted_identifiers: remove_safe` unquoted them without one (`!0 "at"` → `!0 at`), which left SQL that does not parse; such aliases keep their `AS` / quotes. Found by `FuzzTemplates` (seed `1f1e009474bb15ad`); test `TestKeywordAliasStaysParseable`
- `blank_lines: max_N` counted only empty lines: a line of nothing but blanks or tabs kept a run of blank lines apart, and once a later step had trimmed it (the layout, inside a block comment) the next run merged them (not idempotent). Lines of white space count as blank. Found by `FuzzTemplates` (seed `095a1c6df5680a07`); test `TestBlankLinesCountLinesOfBlanks`
- `quoted_identifiers: remove_safe` with a word right behind the closing quote that starts with a letter beyond ASCII (`"a"é`, a type name) glued the unquoted name to it (`aé`): another name, and SQL that does not parse; a blank follows the name now. Found by `FuzzTemplates` (seed `b8b25ce5bd309748`); test `TestUnquotedNameBeforeAGluedWord`
- A comment between `AS` and the alias (`0 AS -- note` / `a`, `1 AS /* x */ b`) was taken for the alias: the alias itself got its `aliases.case` only on the next run (not idempotent), and `aliases.as: add` wrote a second `AS` in front of it (`AS /* x */ AS b`, which does not parse). Found by `FuzzTemplates` (seed `04aea6f677ea6404`); test `TestCommentBetweenAsAndAlias`
- `trailing_whitespace: strip` left form feeds and vertical tabs at the end of lines, so a line holding only a form feed (a page break of old files) was no blank line for `blank_lines` until a later step removed the character and the next run merged the blank lines (not idempotent). Found by `FuzzTemplates` (seed `20adec8188424bb3`); test `TestTrailingWhitespaceStripsFormFeedLines`
- A table or column named `as` behind a dot (`s.as x`, `t.as AS y`) was taken for the keyword: `aliases.as: remove` dropped the table's name (`merge into public.as a` → `merge into public.a`, another table), `add` gave its alias no `AS`, or took the `AS` after the column for the alias and wrote a second one on every run (also when `quoted_identifiers: remove_safe` unquoted the alias, `"t".as "a"`). Found by `FuzzTemplates` (seeds `591a27578ef86a03`, `c525d4bf1bd7bfa7`, `51c807afa6efe50a`); test `TestTableNamedAsIsNoKeyword`
- A three-part name `db.schema.table` had its database taken for the schema: `schema_qualification: remove_public` dropped a database named `public` (`public.s.t` → `s.t`) or the schema `public` after a database (`db.public.t` → `db.t`, which reads `db` as the schema), and the table was not recognized for `tables.case`. Found by `FuzzTemplates` (seed `c66f1fb39eb7538a`); test `TestThreePartNameHasTheSchemaInTheMiddle`
- `arithmetic_spacing: normalize`: an operator before `CAST(…)` (`a%CAST(0 AS t)`) was not taken for arithmetic, and with `cast_style: operator` the next run found `a%0::t` and spaced it (not idempotent); `CAST` starts an operand. Found by `FuzzTemplates` (seed `a38a82e2d2eb5b79`); test `TestArithmeticSpacingBeforeCast`
- `order_asc: remove` dropped every `ASC` keyword, also a name spelled like it: the operator class of an index column (`CREATE INDEX … ((0) s.asc)` → `s.`, which does not parse) and a column label (`SELECT 1 AS asc`, `SELECT 1 asc` → the label was lost). Only sort directions are removed now. Found by `FuzzTemplates` (seed `a59662887ad09768`); test `TestOrderAscRemoveKeepsNamesSpelledAsc`
- `trailing_whitespace: strip` left the blanks at the end of a `--` comment line (they are part of the comment token, not of a gap between tokens); once the comment ended the text (`trailing_newline: strip`), the next run cut them off (not idempotent). They are stripped like any other trailing white space, in PL/pgSQL bodies too. Found by `FuzzTemplates` (seed `513916cdb2dc8819`); test `TestTrailingWhitespaceStripsLineCommentEnd`
- `cast_style: operator` changed the meaning of a `CAST` whose argument is an expression of operators: `CAST(a + 1 AS int)` became `a + 1::int`, which casts only the `1` (likewise `a || b`, `NOT a`, `a IS NULL`, `a IN (…)`, `a AT TIME ZONE …`, `-1`); such arguments keep the parentheses (`(a + 1)::int`). A word right after the `)` (`CAST(0 AS int)AND x`) was glued to the type (`0::intAND x`); it gets a blank. Found by `FuzzTemplates` (seed `6f24f83ebfada270`); test `TestCastStyleOperatorKeepsTheMeaning`
- A schema-qualified table name with white space or a comment around the dot (`public. T`, `s./*x*/t`) was not recognized as a table (its position was taken to follow the dot directly), so `tables.case` left it as written — and once `schema_qualification: remove_public` had dropped `public.`, the next run changed it (not idempotent). Found by `FuzzTemplates` (seed `98f70287bb5e0c8a`); test `TestTableAfterSchemaWithBlanksAroundDot`
- `schema_qualification: remove_public` dropped the schema of a name spelled like a keyword that is no name on its own (`public.as` → `as`, which does not parse; `public.char(1)` → `char(1)`, a cast instead of the function call); such names keep `public.`. Found by `FuzzTemplates` (seed `53f61945df3887dd`); test `TestSchemaQualRemovePublicKeepsKeywordNames`
- Nested block comments (`/* a /* b */ c */`, which PostgreSQL allows) ended at their first `*/` for `blank_lines_between_statements` and `statement_break: always` (a comment after the `;`), for the comment lines and the parenthesis count of the layout, for `syntax_errors: skip` (where a statement starts) and before a PL/pgSQL body: the line break went into the middle of the comment and its rest became code that does not parse. Found by `FuzzTemplates` (seed `87deb96522c135ff`); test `TestNestedBlockCommentAfterSemicolonStaysWhole`
- `aliases.as: add` after a vertical tab, form feed or a single tab (`select (a)\vb`): the `AS` was written after it, where a later rule dropped it (`(a)AS b`) or the next run made it a blank (not idempotent); the white space before an inserted `AS` becomes one blank. Found by `FuzzTemplates` (seeds `035bb8eee64817d0`, `7034725ad045c590`); test `TestAliasAfterVerticalTabGetsABlank`
- `layout.ddl.create_table.align: none | types | all` with a type modifier or default broken after its `(` (`numeric(` / `10)`): the line break became a blank regardless of `paren_spacing`, so with `paren_spacing: remove` the output read `numeric( 10)` and the next run took the blank off (not idempotent). The column split now follows `paren_spacing`, and a line break before a comma (`numeric(1` / `, 0)`) joins without the blank that the next run took off. Found by `FuzzTemplates` (seeds `6f80a3e53954b5f3`, `f48bde497e2d5014`); test `TestCreateTableTypeModifierAcrossLinesFollowsParenSpacing`
- `layout.content.align: preserve` (the default) read the style from a comment when a clause had nothing else (`select --` in a subquery): the first run indented the comment, the next found it on a line of its own and judged the other way (not idempotent). A clause without items gets the indented style. Found by the new `FuzzTemplates` (seed `bed9b188b07948d0`)
- Characters that Go treats as white space but PostgreSQL as part of a name — U+0085 (NEL), U+00A0 (no-break space, often pasted from web pages), U+2028, … — were trimmed off items by the layout, so `select \u0085` (a column of that name) lost its column. Only the six SQL white-space characters (blank, `\t`, `\n`, `\r`, `\f`, `\v`) are trimmed now. Found by `FuzzFormat` (seed `053806b73b808c98`); test `TestNonASCIISpaceIsPartOfAName`
- The query of `DECLARE c [SCROLL] CURSOR [WITH HOLD] FOR SELECT …` was left as written by the layout (a `SELECT` after `FOR` was taken for the command name of `CREATE POLICY … FOR SELECT`), while the same statement in a PL/pgSQL body was laid out; it is now laid out like the query of `CREATE VIEW … AS`. Found with `scripts/body_diff.go`; test `TestDeclareCursorQueryIsLaidOut`
- `layout.subquery.break`: a subquery whose query opens with a parenthesized one (`from ((select 1 union select 2) except select 3) s`, `in ((select 1) union (select 2) order by 1)`) was not opened — only the inner group was, and the rest of the query stayed glued to its `)` (`)` / `except select 3) s`); it is now laid out like any other subquery. Found with `scripts/body_diff.go`; test `TestSubqueryOpeningWithParenthesizedQueryIsOpened`
- `layout.union.blank_line: before` / `both`: a statement that opens with a parenthesized set operation (`(select 1 union select 2) except select 3`) got no blank line before the operator after the group (the group and the operator were written as one piece); it now gets the same blank lines as after any other operand, as it already did inside PL/pgSQL bodies. Found with `scripts/body_diff.go`; test `TestSetOperationAfterParenthesisStartsNoBlankLines`
- A lone carriage return as the line break (CR-only files, or a stray `\r` after a `--` comment) was taken for a blank by the layout: it stayed glued to the code (`0\r, --`) and moved on the next run, or the comment it ends swallowed the rest of the line. A lone CR is now a line break like CRLF: `line_endings: preserve` writes a mostly-CR file with CR again (the line breaks inside string constants do not count when the style of a file is judged), `lf` / `crlf` convert it — inside string constants too, where `\r\r\n` lost one `\r` per run before, and before the layout (a string whose lone `\r` became `\n` only in the output was laid out as a one-line string first and as a multi-line one by the next run). Found by `FuzzFormat` (seeds `dd89d9b768c2ddec`, `50131c43b4d62023`, `97cdd9e570514540`, `49bf2f0c9649092b`, `5c84269ae1e1613a`); cases in `TestLineEndings`
- `line_endings: preserve` changed the line breaks inside multi-line string constants: every CRLF in a string became LF (and `\r\r\n` became `\r\n`, one `\r` less on every run) in a file of mostly LF lines, and every LF in a string became CRLF in a file of mostly CRLF lines — the data of the string changed. They are now left exactly as written; `lf` / `crlf` still convert them as documented. Found by `FuzzFormat` (seed `466d93e6b55233b9`); cases in `TestLineEndings`
- `data_types.form: long` / `long_no_space` rewrote a type name with a modifier list to a long form that takes none (`CREATE TYPE a (default = int2(''))` → `smallint('')`, a column `int4(5)` → `integer(5)`), which does not parse; `int2` / `int4` / `int8` / `bool` / `float4` / `float8` followed by `(` keep their spelling. Found by `FuzzFormat` (seed `29e4894d213c1fab`); test `TestTypeFormLongKeepsNameWithModifier`
- `layout.content.break: always`: an indented comment line above a leading comma that has a `--` comment of its own (`select 0` / ` -- a` / `, -- b` / `1`) kept its source indent (and blank lines above or between them) when the comment after the comma joined it, and the next run took it off (not idempotent). Found by `FuzzFormat` (seeds `10eb365a8c87bc78`, `ac1f8dde162ae558`, `0e4b7e145b1a2d68`)
- A column label spelled like a clause keyword — after `AS` in a select list or `RETURNING` (`select 1 as from`, `a as limit`, `a as union`) or `SELECT` as a bare label (`select 0 select`, also written by `aliases.as: add` as `0 AS select`) — was taken for a clause by the layout and the line broken there, so the output was a different query or did not parse. Found by `FuzzFormat` (seed `b48a1f4e8f6cbccc`); test `TestKeywordAsColumnLabelIsNoClause`
- `layout.content.break: always` with a leading comma followed by a `--` comment with blanks at its end (`select 0` / `,-- ` / `0`): the comment moved to the end of the item above with its blanks (or `\v` / `\f`), which the next run trimmed off (not idempotent). Found by `FuzzFormat` (seeds `8b70a3894a73025f`, `ff0714e4cc19582b`)
- `aliases.as: add` with a table alias followed by a keyword that is no list separator (`UPDATE t b SET x = b`) searched on for the alias, took the later `b` for it and wrote `SET x = AS b` (invalid SQL), while the alias itself got no `AS` (`UPDATE public.accounts a SET …`); a table alias is now the token right after the table name. Found by `FuzzFormat`; test `TestTableAliasIsTheTokenAfterTheName`
- PL/pgSQL bodies: a SQL statement whose `;` stands on a line of its own below a `--` comment (`VALUES (1)` / `, (2)` / `-- , (3)` / `;`) got the `;` written right after the comment, where it became part of the comment — the statement ran on into the next one and the function no longer compiled. The `;` keeps its own line. Found with `scripts/corpus_check.go` on a real schema; test `TestPLpgSQLSemicolonAfterLineCommentStaysOutOfIt`
- Two or more comment lines at the margin in front of an indented select item (`select` / `    a,` / `-- x` / `-- y` / `    b`, a commented-out column list) left the item at its source indent and the next run moved it to the content indent (not idempotent); the extra comment lines no longer count for the common indent of the item. Found with `scripts/corpus_check.go` on a real schema; test `TestCommentLinesAtMarginBeforeIndentedItem`
- `aliases.as: add` after a number that ends in a dot (`select 0."a"`) wrote `0.AS "a"`, and `quoted_identifiers: remove_safe` wrote `0.a` — both lexical errors; the AS or the name gets its blank. Found by `FuzzFormat` / `FuzzTemplates`; tests `TestAliasAfterNumberEndingInDot`, `TestUnquotedAliasAfterNumberEndingInDot`
- `layout.content.break: always`: a block comment on a line of its own below a leading `--` comment of an item (`select -- c` / `/* x */` / `a`) kept the indent of the source — left at the margin next to the indented `-- c`, or one blank off and moved by the next run (not idempotent); the comment lines of an item now stand at its indent, with `comma_position: start` too (where a second comment line kept its source indent or stood at the margin). Found by `FuzzFormat` / `FuzzTemplates`; tests `TestLeadingCommentLinesShareTheItemIndent`, `TestLeadingCommentLinesWithLeadingCommas`
- A name spelled like a statement or clause keyword after a comma, `SELECT`, an operator (`select a, update from t`, `select 0 o, update`, `select a, values from t`, `update t set a = set, b = 0`) or `ON` (`join b on join(0)`, a function) was taken for a clause by the layout: the comma was dropped and the line broken (`a` / `update` / `from t`), so the output was a different query or did not parse. A clause never follows a comma; `update` / `insert` / `delete` / `values` / `merge` right after `select` / `distinct` are names. Found by `FuzzFormat` / `FuzzTemplates`; test `TestColumnNamedLikeStatementKeywordIsNoClause`
- The case rules (`upper`, `lower`, `capitalize`) changed non-ASCII letters of unquoted names too (`ü` → `Ü`, Greek `μ` → `Μ`), which renames the identifier: PostgreSQL folds only `A`–`Z` in an unquoted name of a UTF-8 database. Only ASCII letters are re-cased now. Found by `FuzzFormat`; test `TestIdentifierCaseChangesAsciiLettersOnly`
- `layout.content.break: always` with a comment right after the keyword and a line indented with tabs (alone or mixed with blanks), or further than the item and the lines below it, below it (`select -- c` / `<tab>a` / `+ 1`, `select --` / `      a` / `+ 1`), or a blank line between the comment and the item in a config that indents with spaces: the tab line stayed where it was and the next run moved the item, so the output was not idempotent. Found by `FuzzFormat`; test `TestTabAfterCommentInSpaceIndentIsStable`
- A blank line below a comment inside a broken content item (`where --` / blank / `a = 1` with `layout.content.break: always`) got the item's indent as trailing blanks, which the next run took off again (not idempotent); it stays empty. Found by `FuzzFormat`; test `TestBlankLineAfterCommentHasNoIndent`
- `inequality_op: c` turned `a<>+1` / `a<>-1` (written without spaces) into `a!=+1`, which PostgreSQL reads as the single operator `!=+`; a `<>` with a sign glued to it is kept. Found by `FuzzFormat`; test `TestInequalityCKeepsGluedSignSeparate`
- A quoted identifier that spans several lines (`"a⏎b"`) had its continuation lines indented by the layout, which renames the identifier; like multi-line string constants it is now left exactly as written. Found by `FuzzFormat`; test `TestMultiLineQuotedIdentifierIsData`
- A name after a dot that is spelled like a clause keyword (`from a.join`, `a.from`, `t.where = 1`) started a clause in the layout: the line was broken after the dot (`FROM a.` / `join`) and the second pass read it differently, so the result was not idempotent. Found by `FuzzFormat`; test `TestKeywordAfterDotIsNoClause`
- `aliases.as: add` with a comment right after an implicit alias (`select 0 b -- c \n union select b, a`) did not find the alias, searched on into the next `SELECT` and wrote `SELECT AS b, a` there (invalid SQL); comments after the alias are skipped now. Found by `FuzzFormat`; test `TestAliasFollowedByCommentIsFound`
- PL/pgSQL `CASE` with `case.*.body_break: never` (or `auto`): a `WHEN … THEN` whose body is a nested `IF` / loop / `CASE` was joined to the keyword without a space (`WHEN 'a' THENIF y > 0 THEN`), which is no longer valid PL/pgSQL; such a body now stays on its own lines. Found with `scripts/corpus_check.go` on `incremental_sort.sql` (`function-body-broken`). Test `TestPLpgSQLCaseBodyBreakCollapseKeepsNestedBlock`
- The data lines of `COPY … FROM stdin` (a `pg_dump` file) were parsed as SQL, so such a file failed with a syntax error (or, with `syntax_errors: skip`, only warned): the lines up to the `\.` line are now copied verbatim like an `off`/`on` region and stay directly below the `COPY` statement (a `blank_lines_between_statements` blank line would have become a data row). Tests `TestCopyFromStdinDataIsVerbatim`, `TestCopyFromStdinWithoutTerminatorRunsToTheEnd`
- `--diff` on a large file the formatter changes almost everywhere (20 000 lines) needed about 2.5 GB of memory (quadratic line-comparison table); beyond 16 million cells the differing middle is now shown as removed and added as a whole. Test `TestUnifiedDiffOfHugeChangeIsCheap`
- A lone `-` as the file argument (`pg_procrustes - < q.sql`) was looked up as a file named `-` (and flags after it were ignored); it now means stdin. Test case in `TestReorderArgsBackup`
- A file argument whose name contains glob characters (`v[1].sql`) was treated as a pattern, so with `v1.sql` next to it the wrong file was formatted (and the named one skipped); an existing file is now always taken literally. Test `TestExpandInputsExistingFileWithPatternCharacters`
- Neovim plugin (`:PgProcrustesFormat`): blank lines at the start of the buffer and the blank line at its end were deleted (the output was split with `trimempty`), so the buffer differed from what `pg_procrustes -w` writes and `--check` failed on a file just formatted in the editor; the buffer is now exactly the output of the command line
- `--out-dir` with inputs that land on the same file (`--out-dir out a/x.sql b/x.sql`, or two directories that both hold `x.sql`) silently wrote only the last one; this is now an error that names both inputs. `--out-dir` without files (stdin) is an error too instead of being ignored. Test `TestOutDirClash`
- LSP server: a relative `configPath` in the initialization options (`pgProcrustes.configPath` in VS Code, `lsp.pg_procrustes.initialization_options` in Zed) is looked up below the workspace root, not in the directory the editor started the server in. Test `TestRelativeConfigPathIsBelowTheWorkspaceRoot`
- `syntax_errors: skip` (and `--lines` / LSP range formatting): a statement that starts in the middle of a line — after another statement (`select * from a; select * from b;`) or after the trailing comment of the previous one (`…; -- note` / `…; /* note */`) — took the blanks that separate the two for its indentation: its continuation lines came out one space (or the width of the separator) too far right, and a second run moved them again (not idempotent). Such a statement is now laid out with the indentation of its line, as when the script is formatted as a whole; test `TestSyntaxErrorsSkipStatementsStartingMidLine` compares both paths for every shipped template
- `inline_spacing: normalize` collapsed the indentation of the first line of a file to one space (`    select 1;` at the very start became ` select 1;`); the blanks before the first token of a script are indentation and stay
- `--diff`: the hunk headers named a line 3 before the first line shown and the hunks had no leading context, so `patch` / `git apply` rejected the output; changes closer than 6 lines now share a hunk, and a last line without a newline gets `\ No newline at end of file` instead of running into the next line. Unchanged lines at both ends of the file no longer take part in the line comparison (memory for large files)
- `--backup` without a value (`pg_procrustes -w --backup query.sql`, as documented) took the next argument for the extension — the file was not formatted and the program waited for stdin; a bare `--backup` now means `.bak`, `--backup=.orig` and `--backup .orig` keep working
- `-c path` (and the LSP `configPath`) pointing to a file that does not exist is an error instead of silently formatting with the built-in defaults (which change nothing)
- `--version` and the header of `--print-config` show the release version for builds installed with `go install …@vX.Y.Z` instead of `dev`
- A file that starts with a UTF-8 byte order mark (saved by Windows editors) was a syntax error at line 1 (`syntax error at or near "\ufeffselect"`); the mark stays at the start of the output and the SQL after it is formatted (also with `--lines` and in the LSP server; error columns do not count the mark). Test `TestByteOrderMarkIsKept`
- `-- pg_procrustes: off` / `on`: a line that only looks like a directive because it is a line of a multi-line string constant, quoted identifier or `/* … */` comment started a region (the string was cut in two and the file failed with an error that named the internal placeholder); such a line is data. Directives inside `$$` function bodies work as before. Test `TestDirectiveLineInsideStringOrCommentIsData`
- Error positions in a file with `off` … `on` regions: an unterminated string / comment after a region was reported on the line of the masked text (too early by the lines of the region, with the wrong source line shown), also by `--lines`; an error between two regions was moved down by the lines of the region after it as well; and the byte offset was off by one per digit from the eleventh region on. Test `TestOffOnErrorPositionsAfterRegions`
- `layout.indent.size` with a negative number crashed the program (`panic: strings: negative Repeat count` with `indent.normalize: change`); the config is now rejected: `layout.indent.size` must be 0–32 and `layout.line_length` must not be negative. Test `TestValidateRejectsBadNumbers`

### Security

- `docs/config-builder.html`: the YAML preview is built from DOM nodes with `textContent` instead of concatenated HTML (CodeQL `js/xss-through-dom`), and `escHtml` also escapes `"` and `'` (`js/incomplete-html-attribute-sanitization`)
- `editors/vscode`: `minimatch` is pinned to `^11.0.1` through `overrides` in `package.json` (Dependabot, GHSA-g3hv-75wg-m249: denial of service via globparts amplification); `npm audit` is clean

## [0.6.0] — 2026-11-11

### Added

- `layout.clauses.align: right` — the "river" style: the keywords of a statement's clauses are right-aligned on a common edge (the longest one, e.g. `GROUP BY`) and their content hangs after them (`SELECT a.id,` / `       a.name` / `  FROM accounts` / ` WHERE …`), `JOIN` lines hang under the content of `FROM` instead of widening the river, the columns of `INSERT INTO t (a, b)` line up below the first one, and each query of a `UNION` has its own width. Meant for `content.first_item: inline`; only clauses that are broken take part. Stays idempotent for statements that start indented (`BEGIN; … COMMIT;`, PL/pgSQL bodies: the padding of the first keyword is told apart from the indentation by what all lines of the statement share). Documented in README, reference config and Config Builder (all languages); tests in `internal/layout/river_test.go`
- `keyword_paren_spacing: preserve | add | remove` (default `preserve`) — the space between a keyword or operator word and its `(`, apart from function calls (`call_paren_spacing`): `add` gives `IF (a) THEN`, `WHERE (a = 1) AND (b IN (1, 2))`, `VALUES (1, 2)`, `EXISTS (SELECT 1)`, `ON CONFLICT (id)` (and puts a space between a `)` and the keyword after it), `remove` gives `IF(a)`, `IN(1, 2)`; all shipped templates (`postgresql`, `modern`, `ai`) set `add`; `count(*)`, `coalesce(a, b)`, `varchar(10)`, `INSERT INTO t(a, b)`, `x AS y(a, b)` and keyword-spelled functions (`left(…)`, `replace(…)`, `format(…)`, `json_object(…)`, also inside PL/pgSQL expressions) stay with their own rules. Documented in README, reference config, website, `llms-full.txt` and the Config Builder (all languages); tests `TestKeywordParenSpacing` and test-matrix variants

- DDL layout: `layout.ddl.create_table.break: preserve | never | always | auto` puts every column and table constraint of `CREATE TABLE (…)` on its own line with the closing parenthesis on its own line (trailing options such as `WITH (…)` follow it), `layout.ddl.create_table.align: preserve | none | types | all` pads names and types so columns and constraints line up (table constraints are never aligned), and `layout.ddl.alter_table.break: preserve | never | always | auto` puts each `ALTER TABLE` action on its own indented line (`auto`: several actions or too long). `content.comma_position`, comments (a trailing `-- note` stays with its column) and the indent settings apply; `never` backs off when a line comment is inside; `ALTER TABLE ALL IN TABLESPACE` and `CREATE TABLE … PARTITION OF` are left alone. New golden case `formatter/testdata/ddl_layout`. Also: a `CREATE`/`ALTER` statement without a closing `;` at the end of a script is now processed by the layout like any other
- Layout styles for broken lists and conditions: `layout.content.comma_position: end | start` (leading commas, with the items kept aligned, also for `INSERT` column lists and `VALUES` rows), `layout.content.logical_operator_position: start | end` (`AND`/`OR` opening or ending the line; a comment after the operator stays on its line) and `layout.content.join_on_position: inline | newline` (`ON` and its conditions on indented lines below `JOIN t`; `clauses.join.align: indent` indents `JOIN` under `FROM`). Defaults keep the previous output
- `syntax_errors: fail | skip | ignore` and `--syntax-errors <mode>`: **breaking default** — input that PostgreSQL cannot parse is no longer formatted at token level. `fail` (default) reports every bad statement as `file:line:col: error: …` with the source line and a caret, writes nothing and exits 1 (also in `--check`, `--diff`, `-w` and stdin mode); `skip` formats the statements that parse, leaves the others exactly as written and warns on stderr; `ignore` restores the previous unchecked behaviour. psql meta-commands (`\set`, `\connect`, …) at the start of a statement are kept verbatim and never count as errors; a `BEGIN ATOMIC … END` body is one statement; an unterminated string/comment/dollar quote is fatal in every mode except `ignore`. Library users get `formatter.FormatWithDiagnostics` and the `SyntaxErrors` error type (line, column, message per statement). The syntax check reuses the parse the formatter needs anyway, so valid input costs nothing extra (benchmarks unchanged)
- `capitalize` as a fourth value for every `case:` setting (alongside `upper | lower | preserve`): the first letter of each word is upper-cased and the rest lower-cased (`order_items` → `Order_items`, `character varying` → `Character Varying`, `GROUP BY` → `Group By`); underscores are never removed so identifiers keep their names, quoted identifiers are still never re-cased, and `exceptions` still win. Documented in README, reference config, website and config builder
- Layout support for `MERGE` (PostgreSQL 15+): `MERGE INTO target`, `USING source`, `ON condition` (split at `AND`/`OR`) and every `WHEN [NOT] MATCHED … THEN …` action get their own lines, with the target and each action kept on the keyword line by default; `CASE WHEN` inside an action is not mistaken for a `WHEN` clause, and `MERGE` is recognised inside PL/pgSQL bodies. Separate settings: `layout.clauses.merge` / `merge_on` / `when` (`break`, `align`) and `layout.content.merge_on` (`break`, `first_item`) and `layout.content.when_actions` (`break: always` puts the action on its own line below `THEN`; defaults to `never` and does not inherit `content.break`). New golden case `formatter/testdata/merge`

- New `arithmetic_spacing: preserve | normalize | compact` (default `preserve`, i.e. no change) formats spaces around binary `+ - * / % ^`; only operators proven binary by their neighbours are touched, so unary signs (`x = -1`), wildcards (`SELECT *`, `count(*)`, `t.*`), `%TYPE` and `a - -1` (never `a--1`) stay safe. ### Fixed

- Formatter: function parameter names that are also keywords (`name`, `type`, `event`, `label`) in `CREATE FUNCTION f(name text) RETURNS TABLE(name text)` are no longer upper-cased; this changes the output of existing files that use such names.
- Layout: the `WITH [NO] DATA` / `WITH [CASCADED | LOCAL] CHECK OPTION` trailer of `CREATE [MATERIALIZED] VIEW` and `CREATE TABLE AS` is its own clause instead of being glued to the last `WHERE` condition.
- Formatter: plain column names in `CREATE INDEX … (name) INCLUDE (name)` and CTE names such as `WITH data AS` are no longer upper-cased as keywords.
- PL/pgSQL: `RAISE EXCEPTION` is no longer mistaken for the `EXCEPTION` section when `dollar_quote.plpgsql` restructuring is active (a statement wrapped as `RAISE` / `EXCEPTION '…'` was fused into `raiseexception`); trailing whitespace left behind by the blank-line and DECLARE/BEGIN settings inside dollar-quoted bodies is stripped, so those settings are idempotent
- `not_in: not_equals_all` turned `x NOT IN ('a', 'b')` into `x <> ALL ('a', 'b')`, which PostgreSQL rejects; it now writes `x <> ALL (ARRAY['a', 'b'])` (subqueries are unchanged). `not_in: not_in` turned `x <> ALL (ARRAY['a', 'b'])` into `x NOT IN (ARRAY['a', 'b'])`, which compares `x` with a single array value instead of its elements; it now writes `x NOT IN ('a', 'b')`, converts `<> ALL (SELECT …)`, and leaves `<> ALL (array_column)` alone because no `NOT IN` form exists. Found by the new syntax check (the golden files had recorded the broken output)
- CRLF files were silently converted to LF (the trailing-whitespace pass removed the `\r`); the new `line_endings: preserve` (default) keeps the input's style, and `--check` no longer reports every CRLF file as changed
- Layout: the `AND` of `x BETWEEN a AND b` is no longer treated as a condition separator (it used to put `AND b` on a new line), and the `ON` of a `JOIN` is found at the top level only, so a joined subquery with its own `ON` no longer confuses the split
- Layout: line comments (`-- …`) no longer break the SQL in three more places — `case.break: never` / short `auto` keeps a `CASE` that contains a line comment as written instead of flattening everything after the comment into it; the closing `;` goes on its own line when the statement ends with a line comment (`… -- row two;` left the statement unterminated); and `VALUES` rows keep a same-line comment with their row, also with leading-comma style (`(1, 2) -- one` / `, (3, 4)` produced a stray comma line)
- Formatter: a quoted alias that loses its quotes (`select 1 "a"`) now gets `AS` and follows `aliases.case` in the same pass (it used to be added only on the second run); layout no longer leaves a space before a comma when it joins a line that started with a leading comma (`a , b`)
- Tests: `TestConfigMatrix` now also covers `dollar_quote` / PL/pgSQL (`keyword_indent`, `declare`, `begin_body`, `control_flow` incl. CASE, `end_semicolon`, `declare_when_empty`, boundaries), `paren_indent`, indent normalization, `blank_lines`, `semicolons`, `quoted_identifiers` and `capitalize`, with multi-line PL/pgSQL functions as inputs and a structural check of the parsed PL/pgSQL tree (`ParsePlPgSqlToJSON`, embedded SQL compared by AST fingerprint)
- Layout: per-clause and per-section overrides (`layout.clauses.<clause>.break`, `layout.content.<section>.break`) now take effect even when the global `clauses.break` / `content.break` is `preserve`; previously `IsNoop()` looked only at the global values and skipped layout entirely. Per-clause `break`/`align` values are now validated too (invalid values used to be accepted silently)
- Layout: `SET`, `USING`, `WITH (…)` and `UPDATE` are only treated as clause keywords where they are query clauses; `ALTER TABLE … SET`/`ALTER COLUMN … SET NOT NULL`/`… TYPE … USING`, `ALTER ROLE … SET`, standalone `SET`, `CREATE TABLE … WITH (…)`, `FOR UPDATE`, `ON UPDATE CASCADE`, trigger events (`BEFORE INSERT OR UPDATE`) and `ON CONFLICT … DO UPDATE` no longer get broken into bogus clauses (`DO UPDATE SET` now stays on the `ON CONFLICT` line before `SET`)
- Layout: a leading `SELECT`/`WITH` after a statement prefix (`CREATE VIEW v AS`, `CREATE TABLE t AS`, `EXPLAIN`, …) now starts on its own line when clauses are broken, instead of `CREATE VIEW v AS SELECT` with the rest of the query left-aligned underneath
- Formatter: column names in `ALTER TABLE … ALTER/RENAME/DROP/ADD COLUMN`, in `RENAME COLUMN … TO new` and in `CREATE INDEX … (cols)` are no longer upper-cased when they are unreserved keywords (`label`, `name`, `event`, …)
- Layout: a line comment inside collapsed clause content no longer swallows the code that followed it (`SELECT a, -- c b` after `clauses.break: always`), and `paren_spacing` is honored when multi-line parenthesised content is joined (no more `( SELECT … )`, which also broke idempotence)
- Layout: `clauses.align: indent` keeps the statement-opening keyword (and the first clause) at the base indent instead of shifting it, so the output is stable on re-run; multi-line items with a blank line or a leading comment no longer gain indentation on every pass
- Formatter: `aliases.as: remove` keeps `AS` for aliases PostgreSQL cannot take as bare labels (`month`, `year`, `over`, `filter`, …), which previously produced a syntax error
- Formatter: removing quotes or inserting `AS`/`INNER`/`OUTER` can no longer fuse neighbouring tokens (`select"a"` → `SELECTa`, `"a"where` → `aWHERE`); `arithmetic_spacing: compact` never merges an operator with a following symbol (`0 % +a` → `0%+a`)
- Layout (`internal/layout/layout.go`): with `clauses.break: always` and the default `union.blank_line: preserve`, `UNION`/`INTERSECT`/`EXCEPT` was glued to the preceding token (`uUNION`, `1UNION ALL`), producing invalid SQL; the source gap is now kept and the operator stays on its own line
- Formatter: `operator_spacing` now also normalizes `:=` and `=>` (PL/pgSQL assignment, named arguments); arithmetic operators remain untouched by design
- Formatter: derived-table aliases (`FROM (SELECT …) x`, `LATERAL`, `JOIN (SELECT …) y`) now honor `aliases.as` (add/remove) and `aliases.case`
- Formatter: a single-line gap before the closing dollar-quote delimiter is kept (`END $$` no longer becomes `END$$`)
- Layout: a trailing `-- comment` on a comma-separated item no longer swallows the separating comma (`a -- first,` turned `a, b` into `a b`, an alias); the comma is placed before the comment, and a comment on the same line as the comma stays with its item (stable across passes, also in `INSERT` column lists)

- CLI: prints a `syntax error` warning to stderr when the input does not parse (formatting still falls back to token-level, exit status unchanged); new `formatter.SyntaxError()`
